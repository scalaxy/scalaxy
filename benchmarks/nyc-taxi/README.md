# NYC Taxi Graph Benchmark

The NYC TLC taxi-trip dataset modeled as a property graph, for
testing/benchmarking Scalaxy on a **large** graph database.

## Model

- Nodes: `(:Zone)` — the 263 TLC taxi zones, with `id`, `borough`,
  `zone` properties.
- Relationships: `[:TRIP]` from a pickup zone to a dropoff zone.

Two representations are produced from the same raw trips:

| Mode | Relationships | Relationship properties | Size |
|---|---|---|---|
| `aggregated` | one edge per (pickup, dropoff) zone pair | `trips`, `distance`, `fare`, `passengers` (sums) | 25,711 edges |
| `per-trip` | one edge per trip | `distance`, `fare`, `passengers` | 2,933,097 edges (Jan 2024) |

## Data

- Source: [NYC Taxi & Limousine Commission trip records](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page)
  (taxi zone lookup + yellow-trip parquet, mirrored at
  `d37ci6vzurychx.cloudfront.net`), NYC Open Data.
- Downloaded month: **2024-01** (yellow taxi: 2,964,624 trips;
  2,933,097 have valid in-city pickup/dropoff zones).
- License: TLC trip data is made available under NYC Open Data terms
  (public use).  See the TLC page for the current terms.

## Files

- `prepare.py` — downloads the raw data and generates `zones.csv`,
  `trips.csv` and `trips_aggregated.csv` (requires `pandas` + `pyarrow`).
- `zones.csv` — 263 taxi zones (committed; small).
- `trips_aggregated.csv` — zone-pair aggregated edges (committed; ~600 KB).
- `trips.csv` — per-trip edges (~56 MB for one month; regenerated by
  `prepare.py`, not committed).
- `data/` — raw downloads (parquet + zone lookup; git-ignored).
- `load.lisp` — graph loaders (`load-nyc-taxi`).
- `queries.lisp` — the benchmark query suites (aggregated and per-trip).

## Run

```sh
# aggregated graph (25,711 edges) — fast, no extra setup
sbcl --script scripts/run-benchmark-nyc.lisp aggregated "" 20

# per-trip graph, limited to 200,000 trips — recommended interactive size
sbcl --script scripts/run-benchmark-nyc.lisp per-trip 200000 5

# full per-trip graph (2,933,097 edges) — needs a large heap
sbcl --dynamic-space-size 8192 --script scripts/run-benchmark-nyc.lisp per-trip "" 1
```

Arguments: `mode` (`aggregated` | `per-trip`), `trip-limit`
(`""` = all), `iterations`.

## Reference results (Apple Silicon MacBook, SBCL 2.6.1)

```
aggregated:  load 263 zones + 25,711 edges in ~0.15 s
  count trip relationships                         1 row     ~170 ms
  busiest route                                  5 rows    ~190 ms
  JFK -> Times Sq within 2 hops                  3 rows    ~124 ms

per-trip (100,000 trips):
  load 263 zones + 100,000 edges in ~0.6 s
  count trip relationships                       1 row     ~730 ms
  busiest pickup zones                           5 rows    ~520 ms

per-trip (full 2,933,097 trips, 8 GB heap):
  load in ~20 s (263 zones + 2,933,097 edges)
```

## Scalability notes

- **Storage scales**: the full 2.93M-relationship graph loads in ~20 s
  via the bulk `graph-create-relationship` path (the in-memory store
  skips log I/O when no log path is configured).
- **Query layer is row-materializing**: `MATCH` currently drains matching
  rows into a list before aggregation, so whole-graph aggregation queries
  over the full 2.93M-edge graph need more heap than the interactive
  default.  This is a known area for improvement (streaming aggregation);
  use `trip-limit` to size the benchmark to available memory.
